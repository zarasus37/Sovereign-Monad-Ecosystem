# Sovereign Monad Ecosystem — Learner Onboarding Flow

## Overview
This onboarding flow takes a user from first contact to verified operator status through staged, behavior-based progression. It is designed to make learning feel natural, while preserving real mastery checks.

## Stage 0: Attract
### Goal
Show the learner that the environment offers real agency, meaningful play, and a living society.

### User actions
- Explore the environment.
- Observe what can be done.
- Express intent to participate.

### System actions
- Present agency-rich entry points.
- Highlight that learning is tied to real competence.

### Exit condition
The learner signals interest in binding identity and entering the system.

## Stage 1: Bind
### Goal
Attach identity and establish the learner’s role.

### User actions
- Connect wallet or equivalent identity.
- Accept the Meshaleach role.
- Review constraints and expectations.

### System actions
- Bind identity.
- Initialize limited agency.
- Prepare dormant or partial vehicle state.

### Exit condition
Identity is bound.

## Stage 2: Genesis
### Goal
Capture method through early, low-risk interaction.

### User actions
- Enter the first guided experience.
- Respond to the system’s first constraints.
- Begin to learn the method implicitly.

### System actions
- Repair the broken twin.
- Observe behavior silently.
- Start recording signals of density and method capture.

### Exit condition
Stable bond signals appear.

## Stage 3: Gate
### Goal
Require real refusal, comprehension, and discipline.

### User actions
- Navigate structured constraints.
- Demonstrate comprehension under pressure.
- Show that they can refuse bad paths.

### System actions
- Enforce comprehension gating.
- Open the paper operator path only when ready.

### Exit condition
The learner graduates to paper operator status.

## Stage 4: Operator apprenticeship
### Goal
Move from onboarding to real practice.

### User actions
- Operate in paper or sandbox mode.
- Make decisions under constraints.
- Review consequences and explain reasoning.

### System actions
- Keep Shaliah fully active as coach.
- Provide feedback and attention shielding.
- Keep live capital gated.

### Exit condition
The learner demonstrates repeated voluntary practice and basic spaced return.

## Stage 5: Anti-grind continuous loop
### Goal
Prove cognition through stretch and transfer.

### User actions
- Solve novel variants.
- Transfer skills across contexts.
- Continue through repeated retrieval cycles.

### System actions
- Track telemetry.
- Sign valid mastery events.
- Reject botting, farming, and repetitive loops.

### Exit condition
Integrity-signed proof of cognition.

## Stage 6: Growth Capital (wealth while learning)
### Goal
Build wealth while learning how wealth is created. Default **20%** of eligible Integrity-signed yield becomes Growth Capital—not an agent tax and not a dead lockbox.

### User actions
- See **unitized personal claim** and collective **NAV** (bank-style tracking).
- Confirm deployment choices by risk tier as gates unlock (Shaliah proposes; human confirms).
- Progress **FG-1 → FG-2 → FG-3** via `docs/FG_CURRICULUM.md` (transfer tasks, not quizzes).
- **Cannot change \(r\)** until FG-3; after FG-3 set \(r \in [0.05, 0.30]\) (≤1 change / 30 days); optional seasonal escalate.

### System actions
- Arm Growth Capital at first Integrity-signed eligible \(C\) with \(r = 0.20\) locked.
- Deliver FG lessons L1.1–L3.G with spacing and Integrity-signed gate batteries.
- Pool base deploy + soft liquidity + optional hard goal vault.
- Route \(\alpha/\beta/\gamma = 0.40/0.35/0.25\); issue PoC / Meshaleach Seal on signed mastery.
- Teach through money paths; forbid idle capital as default.

### Exit condition
Claim + NAV readable; FG path visible; at least FG-1 for safe deploys; path to FG-3 rate sovereignty clear; can join higher-stakes economic / event surfaces.

## Stage 7: Societal events
### Goal
Move learning from individual progression to group participation.

### User actions
- Join cohorts.
- Participate in seasons and teach-bridges.
- Learn in public, with others.

### System actions
- Create social learning events.
- Reward contributions that raise the floor for others.

### Exit condition
The learner participates stably in cohort and bridge surfaces.

## Stage 8: Multitude interface
### Goal
Expose the learner to a richer, more complex world.

### User actions
- Work with allies and rivals.
- Navigate jobs and structural tasks.
- Adapt to changing social and economic conditions.

### System actions
- Maintain pruning, routing, and latency control.
- Continue integrity checks on interaction surfaces.

### Exit condition
Integrity-signed transfer across Multitude domains.

## Stage 9: Structural operator
### Goal
Shift from learner to steward.

### User actions
- Take on stewardship roles.
- Handle higher-stakes responsibility.
- Mentor others.

### System actions
- Expand access and authority only within proven envelope.

## Stage 10: Optional L4 residency
### Goal
Support embodied, spatial, multi-generational learning.

### User actions
- Participate in pop-up residencies.
- Learn through physical guild life.

### System actions
- Sync physical and digital state.
- Keep the digital OS functional without requiring residency.

## Stage 11: Continuous co-evolution
### Goal
Preserve learning as a lifelong loop.

### User actions
- Keep stretching.
- Keep contributing.
- Keep re-learning.

### System actions
- Avoid terminal completion logic.
- Open new stretch edges after mastery.

## Operating rules
- Do not advance by clock time alone.
- Do not reward hollow performance.
- Do not let Shaliah become a rival will.
- Do not use static completion as a proxy for real growth.
- Do reward authentic progress, transfer, and return.
