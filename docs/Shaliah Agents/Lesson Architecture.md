# Lesson Architecture

A lesson exists to change what the learner can do under pressure, not what they can recognize on demand.

## Design rules
- Start with a worked example when the learner lacks a schema.
- Shift quickly to retrieval once the pattern is visible.
- Use spacing for retention.
- Use interleaving for discrimination.
- Use fading so scaffolds disappear as competence appears.
- Use metacognitive feedback so the learner explains errors.
- Gate progress on transfer, not completion.

## Lesson phases
1. Orient: state the rule, target skill, and success condition.
2. Model: show one clean worked example.
3. Retrieve: ask for the next step before revealing it.
4. Feedback: confirm, correct, and reflect on the error.
5. Fade: remove one scaffold.
6. Interleave: switch to a related but distinct case.
7. Delay: return after a spacing interval.
8. Transfer: test the same principle in a new surface form.
9. Gate: advance only after delayed transfer and explanation.

## Required ingredients
Every lesson should include:
- one worked example
- one retrieval prompt
- one self-explanation prompt
- one delayed repeat
- one interleaved variant
- one transfer task

## Anti-patterns
- slide decks disguised as lessons
- quiz funnels with no feedback loop
- XP-only progression
- blocked repetition forever
- completion screens mistaken for competence
